## App structure and review points

- `extracted/apktool/AndroidManifest.xml`: `MainApplication` initializes the app; `ui.screen.splash.SplashActivity` launches into `MainActivity`. It declares recording, camera, storage, location and network permissions, along with Firebase messaging, Google ads and billing components.
- `extracted/jadx/sources/mtp/media/karaoke/ui/screen/sing/SingActivity.java` and `.../process/ProcessActivity.java` contain the recording and processing UI. Models and Room storage are under `mtp/media/karaoke/data/`; Kotlin-origin classes have been represented as obfuscated Java by JADX.
- `extracted/jadx/sources/j/a/a/j/f.java`: Retrofit's base URL is `https://api.karavietnam.com/`. This is a static observation only; the server was not contacted.
- `extracted/jadx/sources/j/a/a/j/c.java`: request interceptor sets device/time/version headers, adds bearer authorization if present, and signs a header with HMAC-SHA256 using a key supplied by `NativeUtils.getAppKey()`. The native key value was not recovered or included in this report.
- `extracted/jadx/sources/mtp/media/karaoke/utils/NativeUtils.java`: loads `AudioEngine`; native `getAppKey()` and `getPackage()` depend on compiled libraries. Native C/C++ source is not in the APK.
- `extracted/apktool/lib/`: 27 arm64-v8a, 31 armeabi-v7a, 14 x86, 14 x86_64 libraries. The application also depends on media player, FFmpeg and audio processing binaries; a clean source project would need these compatible prebuilt binaries or licensed replacements.
- `extracted/apktool/res/xml/network_security_config.xml`: cleartext is allowed for `suggestqueries.google.com` and `googleapis.com` (including subdomains). Check whether that exception is still necessary when modernizing the app.
- The manifest sets `android:allowBackup="true"` and targets SDK 30. A privacy review should check whether tokens, recordings and preferences could be backed up; the manifest setting alone does not establish a data-exposure vulnerability. The manifest also declares camera/location permissions: inspect their usage before carrying them into a new build.

## What can be built

The **smali/resource** tree already builds into the unsigned APK above. That is a binary repackaging, not a Gradle compilation from recovered Java/Kotlin source. Neither `build.gradle`, `settings.gradle`, native C/C++ sources nor the original Kotlin source are present in the decoded APK. A claim of a fully buildable original Android Studio project would therefore be misleading.

For a maintainable source project, reconstruct incrementally: start a new Android app with an authorized application ID; import and test manifest/resources; identify Gradle dependencies and generated binding classes; port one screen at a time from the JADX reference while checking its smali; bundle compatible licensed `.so` files by ABI; replace the native key dependency with a supported backend authentication design; validate recording and editing on an offline device before connecting to any service. Preserve only assets and code for which you have reuse rights. No original-source Gradle build or runtime test has been performed here.

- Tested on `Medium_Phone_API_36` (`sdk=36`, `abi=x86_64`) started with `-read-only -no-snapshot -no-boot-anim`. Wi-Fi and mobile data were disabled before installing, and `dumpsys connectivity` showed `Active default network: none` while the app was running. Android's service startup briefly prevented toggling the radios immediately after ADB connected; the app was not installed until offline status was verified.
- The first signed test copy (`hakara-2.1.0-emulator-test.apk`) failed to install: `INSTALL_PARSE_FAILED_MANIFEST_MALFORMED` at the Facebook content provider, whose authority was empty in the rebuilt binary manifest. `aapt dump xmltree` showed the original APK had the nonempty literal `com.facebook.app.FacebookContentProvider{@string/facebook_app_id}` while the Apktool rebuild had `""`. Consequently **the unmodified rebuilt APK is not confirmed installable**.
- A separate `emulator-test-apktool/` copy changes only this manifest field to `com.facebook.app.FacebookContentProvider2387402521276125` (the ID is already present in `res/values/strings.xml`). The original APK and `extracted/apktool/` were not changed. `apktool b`, `zipalign -p 4`, debug signing with the existing Android debug keystore, and `apksigner verify` succeeded. Test artifact: `hakara-2.1.0-emulator-fixed-test.apk` (SHA-256 `9E2E6D7BF8F8EFBF588E30D81C56FC10194DD9160C27EE1B1F1392A31E2A52EF`). Its identity differs from the original APK's signature; it is for emulator testing only.

A UI hierarchy dump showed Home, Explore, Sing, Notification, Profile, search and an offline `Not found song` message. These observations do not establish online login, playback, recording, camera, media export, purchase, or complete feature parity. The emulator's Android 16/x86_64 environment and debug signature differ from the original distribution; recording and backend functionality remain untested.
